# Mimo and standalone Mihomo profiles

## Current managed v3 templates

- [mimo-v3-ipv4-template.yaml](mimo-v3-ipv4-template.yaml): strict destination-family
  enforcement in Rule and Global, with IPv6 capture retained.
- [mimo-v3-dualstack-template.yaml](mimo-v3-dualstack-template.yaml): IPv4/IPv6
  capture and proxy transport in Rule and Global.

Both are generated by `Tests/MihomoRuntimeTests/render_v3.swift` using the same
`MihomoProfile` renderer as the app. Their YAML comments also appear in Mimo's
private installed profile. Comments explain DNS ownership, native exclusions,
family enforcement, ping suppression and verification. These require the pinned
v3 engine and core-owned system DNS; they are not standalone drop-in profiles.
Edit the app's Settings rather than its generated runtime file. Never publish
the runtime file with its local credentials. Current qualification and remaining
limits are in [the implementation record](../Design/MIMO_3_0_IMPLEMENTATION.md).

In the current unpublished candidate, core approves both traffic settings using
one fresh IPv4 exit and one IPv4 allowlist. The private listener has no IPv6
verification user. Dual-stack IPv6 destinations still use the proxy and fail
without native fallback when unsupported; IPv4 approval is not an IPv6
connectivity/exit claim. The templates below were regenerated from that renderer.

The older standalone profiles and their historical results below are retained.

## Rule and Global templates

- [mimo-ipv4-template.yaml](mimo-ipv4-template.yaml): IPv4 DNS defaults with IPv6 capture retained,
  Rule-mode IPv6 rejection when the destination is known, then `MATCH,Proxy` and
  `MATCH,REJECT`. Actual Global mode carries captured IPv6 through the proxy,
  preserving the tested working profile's behavior. Hostname traffic can also
  resolve to IPv6 at the SOCKS proxy. Those proxied paths are permitted.
- [mimo-dualstack-template.yaml](mimo-dualstack-template.yaml): IPv4/IPv6 fake-IP
  DNS and proxy access, ending with `MATCH,Proxy` and `MATCH,REJECT`.

Both default to `mode: rule`. Change only that field to `global`; leave the
groups and rules intact. Their `GLOBAL` and `Proxy` groups have no DIRECT member.
Replace the placeholder server privately before use. Both require the patched
no-ping engine below; captured `ping` and `ping6` are silently dropped, while
native LAN/Tailnet exceptions retain real ping. They use `dns-mode: native` to
register temporary macOS system DNS at the TUN endpoint. UDP/TCP interception and
the diagnostic listener at `127.0.0.1:1053` remain configured. Saved network-service
DNS preferences are not rewritten; the registration belongs to the engine session.

The shared requirement is **no native bypass for captured traffic**: permitted
TCP/UDP uses the selected proxy; failed proxy access must not fall back to DIRECT.
The IPv4 filename describes DNS defaults, not an outstanding IPv6 capture fix.
The [plan summary](../Design/MIMO_DUALSTACK_TEST_PLAN.md#current-plan-summary)
separates this from the managed app's engine-Rule capture-and-reject proposal.

The [completed campaign](../Design/MIMO_DUALSTACK_TEST_RESULTS.md#final-template-results)
ran 3,620 cases: 3,610 met expectations and ten failed. IPv4-oriented passed 905/905
in each mode. Dual-stack passed 900/905 in each mode and is **not deployment-ready**:
LAN/Tailnet short names receive an unwanted fake IPv6 answer alongside the native
IPv4 address. Full names work; the short-name defect also survives reconnect and
reload. The four parser checks passed separately. Existing working profiles and
the two tested templates remain unchanged.

Both templates also have a shutdown boundary: one queued macOS PTR request to
the old TUN DNS endpoint escaped onto the native route after teardown began in
each lifecycle run. No active test-flow bypass was observed, and resolver/TUN
cleanup passed, but standalone shutdown does not guarantee leak-free transitions.

For deployment, use an owner-readable `*.local.yaml` copy with your proxy endpoint
and credentials. Validate it with the pinned engine before starting that engine
alone. Ordinary applications should use system DNS; explicitly querying the
diagnostic listener is not required. Confirm system resolution and both Tailnet
full/short names, then confirm native DNS returns after shutdown. The engine's
native registration retained the tested search list, but dual-stack short-name
answer handling must be corrected before deployment. Physical network switching
and a different same-tailnet peer remain unqualified; the native-name test used
the VM's own Tailscale name. See the
[sample comparison, ownership and acceptance analysis](../Design/MIMO_DUALSTACK_TEST_PLAN.md#final-template-decisions-and-dns-comparison).

When integrating into Mimo's managed runtime, core/supervisor remains the sole
DNS owner and the managed profile must use `dns-mode: disabled`. Do not enable
engine registration alongside Mimo's existing resolver. This template change
does not modify installed services or the frozen standalone profiles below.

## Original Global IPv6 test profile

[mimo-global-ipv6-test.yaml](mimo-global-ipv6-test.yaml) is a standalone
**engine Global, zero-rule** configuration. The private
`mimo-global-ipv6-test.local.yaml` contains the supplied SOCKS5 proxy, is
owner-readable only, and is Git-ignored. Never upload it or package it in a release.

**The current profile requires the [patched test engine](../Patches/README.md),
`v1.19.34-mimo-no-ping.1`. Stock Mihomo rejects `stack: gvisor-no-ping`.**
The installed Mimo app and its engine remain unchanged.

## Current behavior

- `mode: global`, exactly `rules: []`, and `GLOBAL → Proxy → TEST-PROXY`, without a DIRECT fallback.
- Top-level IPv6 enabled, client AAAA answers suppressed, and the default engine IPv6 TUN address; no `inet6-address` override.
- `::/1` and `8000::/1` capture public IPv6 and both NAT64 ranges. IPv4 auto-routing remains enabled.
- **Captured IPv4/IPv6 echo requests are silently dropped.** No direct forwarding, synthetic success or ICMP rejection response. The `gvisor-no-ping` packet handler enforces this; `disable-icmp-forwarding: true` alone cannot do it on stock Mihomo.
- **Native LAN and Tailnet ping remains available.** Connected LAN routes and static Tailnet exclusions keep that traffic outside TUN. Other ICMP control/error types retain their normal handling.
- Static Tailnet IPv4/IPv6 exclusions and native Quad100 for `.ts.net`, without a dynamic Tailscale interface name, provider file or provider port.
- Public DNS through the selected proxy, separate encrypted proxy bootstrap DNS, and local TCP/UDP DNS on `127.0.0.1:1053`.

This test proxies captured IPv6 TCP/UDP through GLOBAL. It deliberately has no
blanket IPv6 rejection or terminal Rule-mode fallback rule. More-specific native
routes remain intentional exceptions; this is not a firewall for interface-bound
traffic outside TUN.

## DNS and use

`tun.dns-mode: disabled` avoids registering a macOS resolver in this standalone
test. TUN port-53 interception remains configured, but DNS on native routes can
bypass it. Query the profile's listener explicitly, or use the mixed SOCKS/HTTP
listener with remote hostname resolution. Do not reuse fake-IP addresses from
another engine. The HTTPS tests obtain their address from **this** listener.

The test engine runs only in `mimo-vm`. Do not start it alongside an installed
Mimo/Clash engine. The local profile is not automatically loaded or installed on
Delta. The separately authorized Delta fixture opens temporary IPv6 application
services and a restricted forwarding proxy; it changes no host routes, PF, DNS
or trust settings.

## Repeatable VM tests

Build using [the pinned-source script](../Scripts/build-no-ping-test-engine.sh),
then copy the binary into a private VM directory. All VM runs require root,
`mimo-vm` hostname, an unused `utun238`, no existing engine, and the exact artifact
checksum. Pass the engine identity explicitly, including to watchdog children:

```bash
sudo /usr/bin/env \
  MIMO_TEST_ENGINE=/private/tmp/TEST/mihomo-no-ping \
  MIMO_TEST_ENGINE_SHA256=CHECKSUM_FROM_BUILD \
  /usr/bin/python3 /private/tmp/TEST/no_ping_profile_test.py /private/tmp/TEST
```

Each test directory must be root-owned, mode 0700. Use a fresh directory for each
Global/DNS run. The scripts leave reports/captures there for inspection; archive
sanitized evidence, then remove the temporary directory and credentials.

### Ping packet test

Copy [no_ping_profile_test.py](../Tests/MihomoRuntimeTests/no_ping_profile_test.py)
and [ipv6_global_profile_test.py](../Tests/MihomoRuntimeTests/ipv6_global_profile_test.py)
into the directory, with the parsed template as `profile.json` and a private
`native.json` mapping `lan_ipv4`, `lan_ipv6`, `tailnet_ipv4`, `tailnet_ipv6` to live
responding addresses. The runner checks native ping first, verifies stock-engine
rejection, then captures on TUN and both native interfaces. All six captured
destinations must receive two requests and zero replies; native targets must
show real request/reply packets outside TUN. Cleanup rechecks native ping,
routes, removed TUN and unchanged DNS.

### Global, DNS and proxy paths

Use `ipv6_global_profile_test.py ROOT FULL_TAILNET_HOSTNAME` with the same engine
environment. Supply the parsed template as `profile.json`. An optional private
`proxy.json` containing one SOCKS5 proxy enables the supplied-proxy case; its
server, port, username and password are the only overridden fields. Without it,
the controlled SOCKS echo case still qualifies IPv6/NAT64 destination transport
and proxy-off failure. The runner removes temporary proxy configuration and its
private input. Every engine has a separate 60-second watchdog.

The supplied-proxy case checks connected MagicDNS A, client AAAA suppression,
local TCP/UDP DNS, proxied public DNS and IPv4 HTTPS. External IPv6/NAT64 HTTPS
results are reported separately: the supplied proxy previously refused these
destinations even without the test engine. This does not prevent local IPv6
transport qualification.

### Real IPv6 HTTPS/UDP on Delta

Create a mode-0700 host directory with a temporary `server.crt` and `server.key`;
the certificate SAN must match the host service IPv6 address. Start:

```bash
python3 Tests/MihomoRuntimeTests/ipv6_local_service_test.py host \
  HOST_TEST_DIRECTORY HOST_VM_BRIDGE_IPV4 HOST_SERVICE_IPV6 VM_IPV4
```

Host mode permits only the VM client and exact test destination/ports, and stops
after 180 seconds. Copy its `fixture.json`, public certificate, parsed template,
and both IPv6 test scripts into a private VM directory. Keep the private key on
the host. Run `ipv6_local_service_test.py vm ROOT` with the same explicit engine
environment. Stop the host fixture afterwards and delete temporary keys/inputs.

The path is VM client → IPv6 TUN → GLOBAL → restricted SOCKS5 proxy → real
`AF_INET6` HTTPS/UDP services. Certificate-verified HTTPS checks the body hash;
UDP tests include fragmented payloads. Proxy-off tests must fail without native
fallback while services remain healthy. The connected-LAN `/64` ordinarily wins
over split-default capture, so a temporary `/128` route forces **only this test
service** into TUN; it is removed afterwards. That route is instrumentation,
not a profile change.

## Current qualification, 2026-11-24

- [Ping evidence](../Tests/MihomoRuntimeTests/Evidence/no-ping-profile.json): 18 checks passed. All twelve captured echo requests were dropped, with zero replies and zero native forwarding. Real native LAN/Tailnet IPv4/IPv6 ping passed before, during and after the test. Stock Mihomo rejected the unsupported stack.
- [Global/DNS evidence](../Tests/MihomoRuntimeTests/Evidence/no-ping-global-profile.json): 22/22 controlled-proxy checks and 26/26 supplied-proxy checks passed, covering IPv6 and both NAT64 TCP/UDP transports, proxy-off failure, connected MagicDNS and DNS/IPv4 HTTPS checks. A remote IPv4 HTTPS probe initially exceeded its four-second deadline; the repeated result and ten-second bound are recorded separately from that failure.
- [Real service evidence](../Tests/MihomoRuntimeTests/Evidence/no-ping-local-services.json): 25 checks passed, including verified 233,472-byte IPv6 HTTPS, UDP requests of 96/1,232/8,224 bytes, no native destination egress, and no direct fallback with the proxy stopped.
- Temporary engines, TUN/capture routes and Delta listeners were removed. VM system DNS and native networking were restored. No PF rules or installed services were changed.

The earlier [stock-engine transport run](../Tests/MihomoRuntimeTests/Evidence/ipv6-global-profile.json)
and [local-service run](../Tests/MihomoRuntimeTests/Evidence/ipv6-local-services.json)
are historical evidence. Their synthetic ping behavior is superseded by the
current no-reply requirement and patched-engine tests.

This does not qualify installed-app lifecycle, system resolver/search-domain
registration, Tailscale disconnect/interface changes, wake, multiple accounts,
all IPv6 protocols or public NAT64 translation. See the
[full analysis](../Design/MIMO_IPV6_PROFILE_ANALYSIS.md).

## Separate dual-stack candidate

[mimo-global-dualstack-test.yaml](mimo-global-dualstack-test.yaml) and its private
`mimo-global-dualstack-test.local.yaml` copy enable IPv6 client DNS and application
access. They change only `dns.ipv6` to `true`, add IPv6 fake pool
`fdfe:dcba:9876:1::/64`, and set the SOCKS5 node's `ip-version` to `dual`. The proxy
address remains IPv4. The working `mimo-global-ipv6-test.local.yaml` is unchanged.

The [results](../Design/MIMO_DUALSTACK_TEST_RESULTS.md) record **48/48 matrix cells
and 6,240 cases matching expectations**, plus 148 successful focused assertions
and one retained `redir-host` diagnostic difference. P07's fake-IP candidate
passed its applicable checks, including actual IPv6 TLS/UDP through the proxy,
failure without native fallback, silent ping dropping and native Tailnet access.
The IPv4-oriented working settings were tested as P00 in all six proxy modes.

This uses the same patched test engine. It preserves disabled macOS resolver
registration; P10 separately tested system DNS and a Safari IPv6 fetch. Automatic
IPv4 retry was not guaranteed when the proxy refused IPv6, although explicit
proxied IPv4 retry worked. The supplied remote proxy's IPv6 capability remains
unqualified. See the results for packet evidence and scope limits.

The [plan](../Design/MIMO_DUALSTACK_TEST_PLAN.md) and
[matrix specification](../Design/MIMO_DUALSTACK_TEST_MATRIX.json) remain available.
The generated P00–P10 `.local.yaml` files are lab variants with transient fixture
endpoints. They are distinct from the new candidate that retains the original
private proxy and public DNS configuration.
